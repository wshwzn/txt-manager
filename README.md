# txt-manager

一个**不需要安装任何东西**的本地纯文本文件管理器。Node.js 单文件后端 + 内嵌前端，双击即用，不用 `npm install`、不联网（Markdown 渲染库也随程序自带）。

为「把一堆 txt / sql / js 小文件堆在同一个文件夹里、需要随手翻看和改两笔」这种场景做的。

## 功能

- **左侧文件列表 + 右侧查看/编辑**：列表支持搜索，按修改时间倒序
- **Ctrl+S 保存**，有未保存改动时列表项带小圆点、文档头显示提示，切换文件前会拦截确认
- **UTF-8 / GBK 编码自动识别**：GBK 文件保存时统一转存为 UTF-8
- **日间 / 夜间主题**一键切换
- **左侧栏宽度可拖动**（160~640px，双击恢复默认）
- **正文字号 9 档可调**（12~24px）：只影响正文，不影响左侧目录字号，所以两者的相对大小关系可调；整体大小仍可用浏览器自带的 Ctrl+滚轮缩放
- **自动折行开关**：长行可选换行显示或横向滚动
- **Markdown 渲染**：`.md` 文件打开时自动进入渲染视图（只读），顶栏「渲染」按钮可手动切换；渲染库是随程序带的本地文件，不走 CDN、断网可用。详见下面「Markdown 渲染」
- **一键显示 / 隐藏文件名后缀**
- **新建 / 删除文件**，删除走 Windows 回收站，可恢复
- **二进制文件保护**：含 NUL 字节的文件（.lnk / .exe / 图片等）判定为非文本，只提示、禁止编辑，避免误保存损坏文件
- **一键切换工作目录**，记住最近使用的 8 个目录；目录选择器是页面内置的，不依赖系统对话框
  - 「最近使用」里的每一条右侧都有 `×`，可以从历史里移除（只删记录，不会动磁盘上的文件夹，也不影响当前目录）
- **手机端自适应**：窄屏下改成「文件列表」与「正文」两屏，点文件进正文、左上角「返回」回列表；按钮加大到适合手指点，正文最小 16px 且强制折行（避免 iOS 聚焦时整页缩放、长行横向拖动）
- **访问口令**：从局域网（手机等）访问需要输一次口令，详见下面「手机访问」

所有界面偏好（主题、后缀显示、侧栏宽度、正文字号、折行）都记在浏览器 localStorage 里，刷新后保持。

## 运行环境

- **Windows**：删除到回收站、盘符枚举等依赖 Windows
- **Node.js 18+**：不需要 `npm install`，本项目零第三方依赖

## 启动

双击 `start.bat`，浏览器会自动打开 <http://127.0.0.1:5177>。

或手动启动：

```
node server.js
```

服务监听 `0.0.0.0:5177`（所有网卡），所以手机在同一网络下也能连进来。重复运行会提示「已在运行」并直接打开页面，不会报错。

启动时控制台会打印两样东西：**可供手机访问的地址**和**访问口令**。

## 手机访问

1. 让手机和电脑连**同一个网络**
2. 在手机浏览器里打开启动时打印的那个地址（形如 `http://192.168.x.x:5177`）
3. 输入控制台里显示的**访问口令**（6 位数字），之后这台手机会记住，不用重复输

几点说明：

- **口令存在 `config.json` 的 `pin` 字段**，首次启动自动生成并打印在控制台。忘记或想改：改这个字段后重启服务即可
- **本机浏览器不需要口令**：从 `127.0.0.1` 发起的请求直接放行——能在这台电脑上发起请求的进程，本来就能直接读到这些文件，口令挡不住也没必要挡
- **连续输错 5 次会锁 5 分钟**（按来源 IP 计），锁定期间即使输对也进不来
- 登录状态只存在服务内存里，**重启服务后所有人都要重新输一次口令**
- Windows 首次启动可能弹出防火墙询问框，要允许（选「专用网络」即可），否则手机连不上
- 若手机打不开，常见原因是：不在同一网络、或所在网络做了客户端隔离（如某些校园网 / 公共 Wi-Fi）

> **⚠️ 如果没有口令，这个服务就是「谁连上谁能读能删」**。它会监听所有网卡，若所在网络能公网访问，端口一旦被人扫到，文件就等于公开了。口令只挡一层，别把它当成万无一失的防护——不需要手机访问时，把 `server.js` 里的 `HOST` 改回 `'127.0.0.1'` 最干净。

## Markdown 渲染

顶栏的 **「渲染」** 按钮用来在「源码」和「渲染结果」之间切换：

- **`.md` / `.markdown` / `.mdown` / `.mkd` 文件打开时自动进入渲染视图**，其他文件默认仍是源码模式
- **手动点按钮只改当前这一份**，不写任何偏好；下次打开文件还是按扩展名自动决定
- 渲染时是**只读**的：编辑框被隐藏，要改就先点回源码。**未保存的内容不会丢**，切来切去都还在
- 渲染中间接掉了两个坑：**原始 HTML 被转义成文字**（笔记里写 `<script>` 只会显示出来，不会执行），**链接一律新窗口打开**（点一下不会把页面从文档管理器带走）
- **图片不自动加载**：渲染成占位框，点一下才真的去请求。远程图片会在打开文件的一瞬间就把你的 IP 和来源地址告诉图片服务器；本地相对路径的图片本服务不提供静态文件，所以只显示文件名
- 超过 **1MB** 的文件不自动渲染，会显示提示（避免大文件卡顿）
- 渲染库是 `lib/markdown-it.min.js`（MIT 许可，v14.1.0），随程序自带的**本地文件**，不需要联网。删掉它也不会崩，只会提示「渲染组件没有加载成功」，源码模式照常可用

> 注意：**Markdown 的语法对普通纯文本是有损的**。比如 `# 开头` 会变成标题、`**文字**` 会变成粗体、`__名字__` 里的双下划线会被当成粗体语法。所以非 `.md` 文件默认不进渲染模式——想让某个 txt 也渲染，手动点一下「渲染」即可。

```
└── README.md
```

## 关于 config.json

程序**只在启动时读一次** config.json，之后全程使用内存里的副本：

```json
{
  "dir": "文档目录的绝对路径",
  "recent": ["最近使用过的目录，最多 8 个"]
}
```

它只在两种情况下被写盘：**切换工作目录**时，以及**从「最近使用」里移除一条记录**时。由此带来两个要知道的现象：

1. **删掉 config.json 后不重启服务，历史目录依然在**——数据在内存里，文件删了不影响运行中的进程；而且只要你再切换一次目录，它就会被重新写回磁盘。
2. **想真正清空配置，必须「删文件 + 重启服务」两步一起做**。只删不重启会白删，只重启不删会读回来。

清空后 `dir` 会回落到默认值（程序自身所在目录），`recent` 变空。

首次运行若没有 config.json，默认工作目录就是**程序所在目录**，因此不需要任何初始化步骤。

## 实现说明

- **零依赖**：服务端只用 Node 内置的 `http` / `fs` / `path` / `vm` / `util` / `crypto`，前端是原生 JS，没有构建步骤、没有 `package.json`。唯一的第三方文件是 `lib/markdown-it.min.js`（MIT），它是可选的——删掉它只是没有渲染功能，其余照常。
- **单文件**：整个前端页面以模板字符串形式内嵌在 `server.js` 里，由服务端直接吐出，不需要静态资源服务器。
- **启动自检**：启动时会用 `vm.Script` 对页面脚本做一次语法解析（不执行），避免前端脚本出错导致「整页交互失效」却悄无声息。
- **防目录穿越**：所有文件操作都经 `safeResolve()` 把路径解析后校验必须落在工作目录内。
- **删除到回收站**：通过 PowerShell 调用 `Microsoft.VisualBasic.FileIO.FileSystem` 把文件移入回收站，而不是永久删除；成功判据是「文件已从磁盘消失」，而非看子进程退出码。

## 快捷键

| 快捷键 | 作用 |
|---|---|
| `Ctrl + S` | 保存当前文档 |
| `Ctrl + 滚轮` | 浏览器原生整页缩放（会等比缩放正文与目录，两者相对比例不变） |
